§ 02 — Problem Statement

Why token-level Hinglish LID is hard

Not sentence-level LID — token-level classification on code-mixed Hinglish social media text. Hindi and English (Roman script) interleaved in the same utterance. Standard LID tools assume clean monolingual input; this breaks that.

Label schema (4 classes)

EN English · HI Hindi / Romanized Hindi · NE named entity · OT other / ambiguous / code-mixed

WordPiece pain

BERT-style tokenizers split Roman Hindi into subwords. Something as basic as yaar becomes ya + ar — which makes naive token-level alignment annoying when you're mapping model outputs back to whitespace tokens.

utterance → yaar I kal going karunga
labels → HI EN EN EN HI

Research context

Corpus collected for an academic data-annotation project (paper under review). ~70% scraped by me; remainder from supervisor-provided sources.

Pseudo-labeling — 3-model voting

No 30k-row manual token annotation team. Ran three existing LID models over every row, mapped outputs to the 4-class schema, then majority-voted per token. HingBERT-LID is binary (EN/HI only) — ended up as tie-breaker, not a strong voter.

SourceModelRole
1HingBERT-LIDBinary EN/HI · WordPiece pain · weak voter
2XLM-RoBERTa-HIEN-LID8-class → mapped to EN/HI/NE/OT
3codeswitch-hineng-lid-linceDictionary pivot → LINCE-trained CodeSwitch

Voting rules

3/3 agree → accept. 2/3 → accept majority. All disagree → keep row (production will see these); ties broken by HingBERT. NE takes priority where present. Forgot to save confidence scores — weighted voting deferred to v2.

§ 04 — Preprocessing Pipeline

Cleaning before labeling

Ran in Spore's notebook environment on CPU (Ryzen 7 5800H, 16GB, no GPU). Full pipeline in Hinglish_data_preprocessing.ipynb.

Step 1

Load & inspect — two source CSVs; compare overlap before merge.

Step 2

Deduplicate — drop intra-set duplicate text rows.

Step 3

Empty rows — drop null/blank text fields.

Step 4

Text normalize — clean_hinglish_text(): strip URLs, emojis, control chars, repeated punctuation; lowercase.

Step 5

Merge — combine unique rows into single corpus (~28,333 rows).

Step 6

Length filter — drop rows with ≤2 or ≥144 whitespace tokens (keeps compute sane, minimal row loss).

Step 7

Export — JSON splits for Kaggle fine-tuning + holdout CSV.

§ 08 — Constraints, Regrets & Next

Honest postmortem

Hard constraints

No local GPU (house fire). Pseudo-labels instead of gold annotation. Severe OT class imbalance. CPU-only labeling on 456k+ tokens.

Regret — Qwen first

Qwen3.5-0.8B overfit on pseudo-labels. Should've started with an encoder baseline.

Regret — no confidence scores

Forgot to save model confidence during pseudo-labeling. Weighted voting would've helped ties — too lazy to re-run.

Regret — HingBERT as voter

Binary classifier dragged Fleiss κ down. Kept as tie-breaker only.

Regret — dictionary → CodeSwitch pivot

Original plan was a dictionary-based 3rd source. Rushed pivot to LINCE CodeSwitch model when dictionary coverage was insufficient.

Next

v2: confidence-weighted voting · replace HingBERT voter · more collection sources · public HF release after paper clearance.
